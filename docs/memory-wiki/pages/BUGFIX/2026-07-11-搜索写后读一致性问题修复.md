# 搜索写后读一致性问题修复

2026年7月11日，用户修复了 oh-memos 项目中存后即搜不命中的问题。根因是 MOSCore.search 的 WorkingMemory 路径中，recall.py 直接取 get_all_memory_items[:top_k]，而 neo4j_community.py 的 Cypher 查询缺少 ORDER BY 子句，导致返回任意存储顺序，刚保存的记忆在截断为 top_k 前就丢失。同时 /search 端点未转发 MCP 的 top_k 参数，恒用默认 MOS_TOP_K=7。修复方案：(a) 在 neo4j_community.py 的 get_all_memory_items 的 Cypher 中增加 ORDER BY coalesce(n.updated_at,n.created_at) DESC，并删除两处多余 print；(b) 在 start_api.py 的 SearchRequest 中增加 top_k 字段，/search 转发 top_k。验证结果：新存 PROBE-FB9977 后立即 memos_search 命中并排 #1。
