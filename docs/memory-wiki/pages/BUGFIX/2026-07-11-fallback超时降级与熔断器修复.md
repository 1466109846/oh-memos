# fallback超时降级与熔断器修复

2026年7月11日，用户修复了 oh-memos 项目中 deepseek 超时时 fallback 降级过慢的问题。根因是 openai SDK 客户端 max_retries=3 乘以 read timeout=120s，单次 generate 内部耗时约 360s，且多 chunk 提炼时每个 chunk 都重新撞击主模型。修复方案（涉及 src/oh_memos/llms/fallback.py、configs/llm.py、configs/env_loader.py）：(a) classify_error 中拆出 unresponsive 类别（超时/连接错误）→ 立即降级不重试；(b) _fast_fail_primary 将主模型 openai 客户端改为 max_retries=0 + timeout=primary_timeout（默认60s，可通过 MOS_CHAT_FALLBACK_PRIMARY_TIMEOUT 配置）；(c) 增加熔断器：主模型失败后冷却期内直接走 fallback、跳过主模型，避免多 chunk 请求每次重撞。验证结果：deepseek 挂起（HTTP 000）时，短/长记忆 memos_save 均成功；熔断器单测中 primary 只调用1次、fallback 调用3次。
