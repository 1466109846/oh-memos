# Cube自动注册问题修复与API启动优化

2026年3月10日，用户报告并修复了cube不能自动注册的bug。该问题源于`ensure_cube_registered()`函数过度依赖模板cube的存在性检查，忽略了已有的环境变量回退机制。修复措施包括：在`mcp-server/cube_manager.py`中移除`ensure_cube_registered`中多余的模板前置检查，直接调用`ensure_cube_directory`；在`mcp-server/handlers/admin.py`中使`handle_memos_register_cube`在找不到cube时能自动创建目录；并在`mcp-server-node/src/cube-manager.ts`和`mcp-server-node/src/handlers/admin.ts`中同步修复相关逻辑。此外，为解决API启动缓慢问题，用户分析发现串行初始化所有cube导致性能瓶颈，遂决定改为仅启动时注册默认cube（dev_cube），其余cube采用按需注册方式。为此新增MEMOS_STARTUP_CUBES环境变量以灵活控制启动cube数量（支持指定具体cube或'all'），同时在每个cube注册过程添加耗时日志记录用于监控。验证方法包括使用不存在的project_path `/mnt/g/test/test-auto-cube`调用memos_search测试自动创建功能，以及通过REST API访问未注册cube触发自动注册流程。
