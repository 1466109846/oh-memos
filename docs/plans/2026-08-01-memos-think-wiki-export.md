# memos_think + wiki 导出 实施方案

> 背景调研: `docs/research/2026-08-01-llm-wiki-gbrain.md`(GBrain 的 think/合成 + Karpathy LLM Wiki 的答案回灌与 markdown 载体)。
> 已确认决策: think 用**证据包模式**(合成留给调用方 Claude); 回灌新增 **SYNTHESIS** 类型; wiki 默认导出到**目标项目 `docs/memory-wiki/`**。
> token 优化(工具合并/描述瘦身)本轮不做,但两个新工具的描述按瘦身标准写(≤6 行),并通过 `schema:budget` 检查。

## 0. 关键架构结论(地形调查得出)

1. **两个功能均零 Python 后端改动。**
   - think 所需检索走现有 `POST /product/search`;矛盾/过期/缺口是查询时规则级计算,在 Node handler 内完成(现有 CONFLICT 边只在默认关闭的 reorganizer 里创建,不可依赖)。
   - wiki 数据走现有 `POST /product/graph/data`(`Neo4jGraphDB.export_graph`,`src/oh_memos/graph_dbs/neo4j.py:1690`),返回 `{nodes:[{id, memory, metadata}], edges:[{source,target,type}], total_nodes, total_edges}`,支持分页。
2. **文件写入必须在 Node 侧**:Python API 跑在 Windows,无法解释 WSL 语义的 `project_path`(`/mnt/g/...`);Node MCP server 跑在客户端侧,路径语义天然一致。
3. **Python 不校验 memory_type**(枚举只在 Node 侧),SYNTHESIS 新增只动 Node + 可能的 GUI/hooks 文案。
4. Node 侧可复用件:`getCubeIdFromArgs`/`ensureCubeRegistered`(cube 路由)、`query-processing.ts`(意图/关键词/rerank)、`keyword-enhancer.ts`(levenshtein)、`getTemporalMemories`(Neo4j 直查最近记忆,`handlers/search.ts:38`)、`formatters.ts` 的 mermaid 生成、`arg-contract.ts`(DECLARED_KEYS 从 toolSchemas 自动派生,新工具零登记)。

## 1. memos_think — 证据包 + 缺口分析

### 接口(tools-registry.ts)

```
memos_think:
  query: string                    # 要回答的问题
  project_path / cube_id           # 复用 projectPathParam/cubeIdParam
  top_k?: number = 15              # 证据检索量(比普通 search 大)
  fresh_days?: number = 30         # 超过视为"可能过期"的阈值(仅 PROGRESS/FEATURE 等时效类)
```

描述(瘦身标准,要点):"检索证据并做矛盾/过期/缺口标注,返回带编号引用的证据包;由你(调用方)合成最终回答;若答案有沉淀价值,用 memos_save(memory_type=\"SYNTHESIS\") 回灌,内容中保留 [n]→memory_id 映射。"

### 流程(handlers/think.ts,新文件)

1. cube 解析 + 探活(现成工具函数)。
2. 主检索:`POST /product/search`(top_k=15,不 compact);并行 `getTemporalMemories`(最近 72h,top 5)补时效证据;两路按 id 去重合并。
3. **证据编号**:[1][2]… 每条带 id、memory_type、key、updated_at、confidence。
4. **矛盾/演进候选**(规则级,两两比对):tags 交集 ≥2 或 key 归一化后 levenshtein 相似,且 updated_at 相差 > fresh_days → 标注"同主题新旧对,以新为准/可能矛盾"。
5. **过期候选**:updated_at 超过 fresh_days 的 PROGRESS;status ≠ activated 的一律标注。
6. **缺口分析**:对 query 分词(复用 keyword-enhancer 的关键词抽取,CJK bigram 兼容),统计每个关键词在证据全文中的覆盖;未覆盖关键词列为"记忆库中没有的信息"。
7. 输出 markdown 结构:`## 📚 证据` / `## ⚖️ 矛盾与演进候选` / `## ⏳ 可能过期` / `## 🕳️ 缺口(记忆库没有的)` / `## 下一步`(固定文案:指导调用方合成+引用+可选 SYNTHESIS 回灌)。

### 注册属性

- WRITE_TOOLS:**不加**(纯读)。REMOTE_TOOLS:**加**(走 /product/search,embeds query)。

## 2. memos_export_wiki — cube → 互链 markdown 镜像

### 接口

```
memos_export_wiki:
  project_path / cube_id           # 复用共享参数
  output_dir?: string              # 默认 <project_path>/docs/memory-wiki;二者均缺 → 报错
  include_archived?: boolean = false
```

### 流程(handlers/wiki-export.ts,新文件)

1. cube 解析;`POST /product/graph/data` 分页拉全量(page_size=100,循环到 total_nodes)。
2. 过滤:排除 WorkingMemory 层级节点(注意:节点的记忆层级 WorkingMemory/LongTermMemory/UserMemory 与业务 memory_type(存于 tags)是两个维度);默认排除 status ≠ activated。
3. 渲染规则:
   - **每条记忆一页** `pages/<TYPE>/<yyyy-mm-dd>-<slug>.md`:slug 取 key 归一化(非法字符→`-`,截 60 字符,冲突追加 id 前 8 位);YAML frontmatter(id/type/tags/status/confidence/created/updated);正文 = memory 全文;尾部"## 关联"段:来自 edges 的 `[[wikilink]]`(CAUSE→导致 / RELATE→相关 / CONDITION→前提 / CONFLICT→冲突)。
   - **index.md**:生成标记注释 + 按 memory_type 分组目录(每条:标题+日期+相对链接)+ 统计(N 页/M 边/导出时间)。
   - **graph.md**:mermaid 总览(复用 formatters.ts 既有 mermaid 逻辑;节点 > 80 时跳过并注明)。
4. **写入安全策略**(写的是用户项目目录,必须保守):
   - 每个生成文件首行注释标记 `<!-- generated by oh-memos wiki-export -->`;
   - 重导出时只删除带该标记的 `.md`,目录里任何无标记文件一律不动并在结果中列出警告;
   - 不做任何 git 操作,只在输出末尾提示用户可自行 `git add docs/memory-wiki`。
5. 输出:页数统计、目录树摘要、跳过/警告列表。

### 注册属性

- WRITE_TOOLS:**加**(写文件系统,readOnlyHint=false 防止 client 静默放行)。REMOTE_TOOLS:不加(graph/data 不 embed)。

## 5. 实施顺序与验证

1. 全仓 grep 类型硬编码收口清单(§3 最后一行)→ 定稿 SYNTHESIS 改动点。
2. SYNTHESIS 枚举接入(小,先行)。
3. think.ts:实现 → tsc → stdio 探针(initialize/tools/call)对 `oh_memos_cube` 跑真实 query(如"BM25 为什么默认关闭"),人工核验证据编号/矛盾对/缺口段合理。
4. wiki-export.ts:实现 → 先导出到临时目录核验(frontmatter/wikilink/index/标记删除逻辑:预置一个无标记文件确认不被删)→ 再导出本项目 `docs/memory-wiki/` 作为 dogfood。
5. `npm run schema:budget`(超了则精简描述,而不是直接 freeze)→ `npm run build`。
6. 端到端:重启 MCP 客户端,真实调用 memos_think → 用 memos_save(SYNTHESIS) 回灌一条 → memos_search 能检回且带 🧠 标识。
7. 收尾:memos_save 记录 FEATURE 记忆;不 commit(除非用户要求)。

## 6. 风险与对策

- `graph/data` 返回的 metadata 是否含全量字段(sources/背景):实现前打一发真实请求确认;缺字段则 wiki 页 frontmatter 相应裁剪(不为此加后端端点)。
- 大 cube 导出:分页循环 + max 500 页硬上限,超出报错要求缩小范围。
- 写用户项目目录:仅标记文件可删;output_dir 不存在时递归创建;绝不 touch 目录外路径(路径规范化后校验前缀)。
- schema budget 超限:优先砍描述,两个新工具合计控制在 ~500 tokens 内,不放大现有 token 问题。
